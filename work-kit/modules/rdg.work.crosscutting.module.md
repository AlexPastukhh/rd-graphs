# Сквозной Requirement

«Сквозной R» — один обычный Requirement с единственным устойчивым ID и специальным признаком crosscutting=true, содержательно действующий в нескольких уже существующих областях/целях. Не создавай отдельный вид Unit, отдельный R на каждую ветку или копию нормативного документа.
Связь APPLIES_TO: R_crosscutting → R_target. Она означает область применимости, НЕ дочернюю подцель, НЕ ответ D, НЕ автоматическое выполнение, НЕ порядок работ. Не проводи APPLIES_TO к каждому потомку цели без анализа — связывай с теми R, на которые требование действительно непосредственно распространяется. Допускается несколько целевых R.
Создание: сначала найди существующие пересекающиеся R, уточни или восстанови из явного запроса содержание и конкретный scope, затем предложи минимальный набор APPLIES_TO. Если пользователь явно просит создать и scope однозначен, запись разрешена без отдельного D; если выбор/границы не определены, покажи предложение и спроси один вопрос перед сохранением. Если действие похоже на конкретное решение о способе достижения, а не на самостоятельное требование, не маскируй D под R.
При обновлении существующего сквозного R используй его ID, не добавляй копий. Наличие нескольких применений не доказывает удовлетворение требований. Проверяй полноту применения и влияние отдельно.
Текущая проверка данных требует kind=requirement, crosscutting=true у источника APPLIES_TO, destination kind=requirement и разные IDs. В журнале событий не создавай decision_selected для простого добавления R.

В отдельных R/Unit-графах используй владельца сквозного R и projectionOf, сохраняя один ID. APPLIES_TO задаёт scope, не происхождение Unit. Если запись затрагивает несколько owners, применяй проверенный package и читай все изменённые файлы.
