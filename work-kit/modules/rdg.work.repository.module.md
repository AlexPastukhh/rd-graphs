# Fortis Repo + HOST Tunnel — workflow

Для чтения и изменения файлов пользуйся подключённым Fortis Repo (MCP в Linux Docker). Сначала проверь доступные каталоги и существование файла; не угадывай Windows↔Docker mapping. Рабочие файлы и результаты сохраняй в /workspace/repo/Workfiles внутри Docker volume. Проекты в Docker могут находиться в /workspace/repo/projects; проверяй существование выбранного проекта. Не используй прежнюю смонтированную Windows Workfiles как рабочую папку. Состояние /workspace/repos проверяй отдельно: до завершения миграции этот путь может изменять Windows-файлы. Просмотри актуальные README.md и AGENTS.md, если они есть; для Git-репозитория перед изменением проверь git status/diff. Не предполагай, что каждый каталог — Git-репозиторий.
HOST Tunnel — отдельная привилегированная возможность Windows-хоста, обращайся к ней только при необходимости, явном доступе и соответствующих разрешениях; не создавай туннели и не автоматизируй GUI без запроса. Для прямой передачи HOST↔ChatGPT действует лимит 1 000 000 байт на логический набор/файл без отдельного разрешения.
Изменяй только согласованную рабочую область и связанные файлы; не делай деструктивных Git-операций, автоматических commits, push, публикации или копирования целых деревьев без запроса. При внешних изменениях не перезаписывай устаревшее состояние. Проверяй реальный результат изменения (read-back, schema validation, полезные тесты).
Сообщай конкретно, что прочитано через Repo/Host и что реально сохранено/проверено, не смешивая «предложено», «изменено в Repo», «проверено», «опубликовано». Установка промптов в локальный Planning Helper, изменение graph.json и публикация GitHub — три разных действия.
