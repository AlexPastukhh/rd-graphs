# RDG — проверенные примеры и способы их использования

Источники примеров хранятся в Fortis Repo, отдельно от рабочих graph.json. **Индекс и карта покрытия**:
`/workspace/repos/rd-graphs/docs/examples/EXAMPLE-COVERAGE.md`.
**Исходный предоставленный пользователем документ**, сохранённый дословно:
`/workspace/repos/rd-graphs/docs/examples/requirements-decisions-graph-examples-v0.2.source.md`
(оригинальное имя: `requirements-decisions-graph-examples-v0.1(2).md`, содержимое версии 0.2).

В каталоге браузерного R–D Viewer доступны три учебные проекции **исходного файла**, не предназначенные для записи:
- `graphs/examples/reference-app-definition/graph.json` — App Definition: семь соседних R, потребности Scenario и Feature, контекст и Realization Requirements (§1–2).
- `graphs/examples/reference-delegation-status/graph.json` — делегация одного R-ID, внутренний ответ, функциональная потребность, QRPE и граница достаточности (§3).
- `graphs/examples/reference-behavior-review/graph.json` — конкретный выбор против reusable variant, общий vs локальный scope, кандидаты, изменение контекста и условная история (§4–5).

**Исторический многоуровневый набор графов по отдельным R текущих графовых проекций (новый условный пример, НЕ источник v0.2):** `graphs/examples/reference-complete-app/graph.json` → ещё шесть уровней в том же `identitySpace`, с неизменными `SH-*` Requirements при переходе между файлами. Показывает 17 различных типов отношений, **7 типов имеют рабочую поддержку writer в v7, остальные только Viewer/учебную проекцию**: готовое `PER_ITEM 1..N` против конкретно двух Features, одну общую `TM-FEATURE` и два применения, сквозной R, контекст, уточнение, потребность из Scenario, QRPE, pending Proposal, локальные решения, а также разницу реального (но только в сюжете) пересмотра и непринятого предложения. Удобный маршрут и построчная таблица покрытий: `docs/examples/COMPLETE-REFERENCE-GUIDE.md`. `SH-*` и события `by=example-only` не копируй в рабочий проект.

**Прежняя минимальная многоуровневая учебная проекция (НЕ часть исходного v0.2)**: входной `graphs/examples/reference-feature-root/graph.json` (один корневой R) → по дочернему R «Расписать функционал» в `graphs/examples/reference-reusable-vs-concrete/graph.json` (корень — ТОТ ЖЕ R; варианты «через Features `PER_ITEM 1..N` с одной готовой `TM-FEATURE` Model» или «иначе», затем ОДНО выбранное только в условном примере D вводит РОВНО четыре R) → по дочерней R в `graphs/examples/reference-feature-{auth,catalog,cart,payment}/graph.json` (каждый следующий уровень начинается с идентичного R, оставляя его конкретные решения открытыми). Способ «через Features» — решение на уровне R «Расписать функционал», а НЕ часть формулировки исходного R и НЕ указание его родителя. Подготовленный `1..N` вариант **не создаёт** фактические ветви до конкретного выбора. Новые `DEMO-*`, отображаемые поля и ребра — выдуманные read-only учебные данные; не превращай их в выбранные решения пользователя. Связи между этими графами теперь **производятся автоматически через идентичность R**, а не задаются прямой ссылкой файла на файл: исходное `INTRODUCES` вводит R, отдельный уровень объявляет тот же `rootRequirementId`, оба имеют общий `identitySpace`. Точные связи по файлам и визуализация всей папки: `docs/examples/GRAPH-IDENTITY-AND-FOLDER-MAP.md`. Подробно: `docs/examples/EXAMPLE-COVERAGE.md`.

Читай **релевантный фрагмент** примеров при обсуждении сложного структурного вопроса или когда пользователь просит показать, как работает граф. Не копируй `EX-*` и `DEMO-*` IDs или условные Decisions в новый рабочий проект и не навязывай структуру App Definition любой цели. Исходник не выбирает обязательный набор типов графового хранилища или контракт каждого Target Module. Для спорных моментов приоритет за его текстом, не за упрощённой JSON-проекцией.

Смысловые слои связей и их отображение подписанными стрелками описаны в `docs/examples/RELATION-SEMANTICS-AND-VIEW.md`: разбиение, основания, происхождение R, готовые варианты, QRPE/пересмотр и область применения. **Не превращай вспомогательные связи в INTRODUCES** и не объявляй рассмотрение кандидата состоявшимся изменением D.

Reference-графы содержат **иллюстративные** связи и события, которые Viewer умеет отображать, но текущий `graph-apply.py` **не** умеет записывать: `INFORMS`, `IDENTIFIES`, `REVEALS_NEED`, `QRPE_FOR`, `USES_VARIANT`, `RECONSIDERS`, `context_changed`, `candidates_prepared`. Не обещай эти операции без уточнения физического формата и расширения updater. Контекст и содержимое другого решения могут выступать драйверами — не превращай любой драйвер в Requirement.

`graphs/examples/example/graph.json` — минимальный smoke-пример (9 узлов), НЕ полный корпус. `graphs/workspaces/try-it/graph.json` — отдельный тестовый рабочий граф, где пользователь сам принимает решения; reference-примеры не являются её начальным содержимым.

Для просмотра: «Граф R–D» → папка «Примеры» → **«Связи графов»** (карта связанных и самостоятельных графов, стрелки подписаны понятным смыслом и точными ID в инспекторе R) или **«Карточки»**; подуровни открываются из дочернего R. Для полноценного чтения основания/ограничений открой индекс или исходный Markdown; не делай выводы о выполнении приложения по иллюстративной схеме.

Revision 3 связанных графов R дополняет перечень типов содержательными случаями: конкретные части Scenario информируют границы Feature; общее SH-D-BEHAVIOR-SHARED действует на Availability/Reservation; их локальные State D различаются; один SH-D-STATUS отвечает функциональной потребности и части локального R ошибок с условной достаточностью. Передача SH-R-SCREATE адресует конкретный SH-TM-SCREATE и внутренний ответ. projectionOf указывает владельца того же ID, а не новый объект. Эти поля остаются иллюстративными, не новыми операциями writer.

## Целый модуль и отдельные Units

docs/examples/MODULE-UNIT-GUIDE.md; вход graphs/examples/reference-module-units/graph.json.
reference-unit-direct показывает узкий R с прямым готовым D.
reference-unit-split показывает оправданное разбиение на reference-unit-states и reference-unit-transitions.
Все подготовлены, не приняты. Общая карта показывает TM, Unit-графы открываются из родительского R.

2D: десять широких template-tm-2d-* и 38 отдельных *-unit-ru-* графов; IDs сохранены. Unit-источник — ссылка на owner полного исходника, без 38 копий Markdown.
SH: отдельные Unit-графы для состояний, ошибок, результата, обратной связи, границ и отмены; D общие через projectionOf.
DEMO: четыре узких Feature-графа помечены Unit. Различие масштаба — по задаче, не по числу нод.

Подписи различают «готовое разбиение · под-R», выбранное INTRODUCES, DERIVES и раскрытие той же записи. Ни одна из этих связей сама по себе не доказывает выполнение. Пример по одному R не называется «полным примером». Режим всех графов не реализован.

## v7: два дополнительных учебных примера (не actual user consent)

\`graphs/examples/reference-prepared-planning-tree/graph.json\`: read-only дерево prepared вариантов, у каждой показанной потенциальной R по два собственных способа/канона, одна дополнительная глубина, никакой принятой реальной D. Первая ветвь разбиения не становится project state от простого просмотра.

\`graphs/examples/reference-mixed-active-work/graph.json\`: read-only условная имитация рабочего состояния: два ready + один situational option, отдельные +/- canonBlock, общий composite, QRPE до выбора и после него, T1/T2/T3, два вида R от одного выбранного только в учебном сюжете D, независимые категории и 3×10 потенциальных R, скрытых в коллекциях. Реальные пользовательские decisions/events в этот файл не записываются. В Viewer R с выбранным D по умолчанию показывает его фактическую ветвь, но дочерняя R без выбора показывает все собственные варианты.

**Ни один из этих примеров не заменяет настоящий workspace** и не даёт права переносить \`exampleOnly\` D в user project. Объяснения и операции пилота: docs/guides/RDG-V7-WORKING-GRAPHS.md.
