## Краткий результат

Дочерний результат теперь распространяется через точные projectionOf/expansionOf
на обязательную композицию нескольких graph.json одного Graph root.
Writer сохраняет производные достижения/выполнения в настоящих владельцах.
Activity/workflow используют тот же расчёт: размещённое выполненное исчезает
из будущего и видно в истории; Plan при этом не переписывается.

Один Action остаётся одним экземпляром. Непринятые предки не активируются
от выбора в глубокой ветви. Повторные проекции не дублируют действие. Выполнение
C → отзыв C → выполнение C2 сохраняет все три факта. Изменение исполненного C
не создаёт второе исполнение и не возвращает его автоматически в будущее.

Финальная общая регрессия: **259 Python tests; Node 415 cases: 413 PASS,
0 FAIL, 2 SKIP**. В Python входят 19 межфайловых проверок. Два требующих живого
Helper Node-сценария отдельно выполнены внутри Python acceptance с настоящими
writers; DOM имитируется. Native Windows/G2 и полный новый Gendocen context
остаются непроверенными.

Ниже: состав и границы; оси с evidence; дефекты, найденные до завершения;
точные проверки; ограничения и следующий шаг. Исходные before-копии, SHA-256
и выбранный diff лежат рядом. Новых нормативных Need/FR/Scenario/SRU не принято.

## Состав и поведение

- Новый tools/rdg-completion-context.py загружает авторизованные workspace owners
  из опубликованного catalog затронутого identitySpace. Временное объединение
  нужно для расчёта; отдельный сохранённый owner или копия проекта не создаётся.
- Semantic owner уникален. Projection разрешается по точным graphSlug/nodeId,
  с проверкой ID, kind, identitySpace и нормативного scope. Continuation root
  имеет точное expansionOf, совпадающее с projectionOf этой R.
- Общий completion_state остаётся единственным алгоритмом результата. subgoal
  участвует в достижении родительской R; method_correctness — в выполнении
  соответствующего Action. Местный выбор под непринятым предком не активирует ветвь.
- При выборе Action под projected R сохраняется driverOwnerSnapshot с определением
  настоящего owner. Прежний driverSnapshot локального отображения сохраняется.
- Package writer рассчитывает финальную композицию и добавляет готовые производные
  события в реальные владельцы. Явный результат/выбор Action через его проекцию
  отклоняется. Отношения повторного показа не добавляют обязательных исполнений.
- Нужны read scopes всех загруженных источников. Каждое новое производное событие
  межфайлового пакета требует result permission либо graph.write у owner,
  включая owner, уже указанный с обычной правкой в исходном запросе.
- Source/catalog hashes и grants повторно проверяются до durable acceptance.
  Общий writer lock, prepared journal, recovery и read lock защищают штатный
  многофайловый путь. Физическая запись нескольких файлов не объявляется atomic rename.
- Лента берёт compositionOrder только из завершённого журнала с completionReadSet.
  Исходные факты идут перед производными, производные — по зависимостям; у каждого
  остаются graphFile и исходный ID. Проекция получает ownerRef настоящей сущности.
- Helper имеет один фиксированный файл прямой записи, но читает всю разрешённую
  композицию. В continuation-root можно создать Action этого файла и разместить
  projected R. Производные родительские записи делает штатный writer с проверкой прав.
- Viewer source 2.2.0 включает общий UI-модуль через штатный builder. Защита
  protected/stable проверяется по настоящей R на прежних policy callsites.
  Ручной Helper сохраняет свой более узкий отказ при protected R в компоненте.

## Что обнаружено и исправлено до завершения

1. Первый общий Node run: 411 PASS, 2 FAIL, 2 SKIP. Два старых cross-file теста
   копировали writer без нового resolver. Списки зависимостей fixtures обновлены;
   отдельный повтор дал 28/28 PASS, затем общий Node run дал 413 PASS/2 SKIP.
   Код разрешения не ослаблен ради этих тестов.
2. Независимый контрпример показал обход result permission: исходный пакет явно
   содержал child execution и обычную правку родительской R, поэтому parent считался
   уже авторизованным по праву обычной правки. Производные результаты при этом
   сохранялись без result permission. Исправление проверяет каждое новое производное
   событие межфайлового пакета независимо от исходного списка owners.
   [До исправления](permission-counterexample-before.log) и
   [после исправления](permission-counterexample-after.log).
   После этого заново выполнен полный общий прогон.
3. В действующих руководствах удалены устаревшие фразы о невозможности
   межфайлового расчёта и отсутствии ручной ленты. Исторические checkpoints
   и прежняя матрица P2 не переписаны.

## Ограничения и следующий шаг

- Один Graph root, опубликованный writer/catalog/common-lock protocol и writable
  candidate-v6 workspace owners. Legacy/prepared/read-only/cross-project контекст
  не импортируется как актуальная обязательная композиция.
- Читаются все опубликованные workspace-файлы затронутого identitySpace, включая
  предварительные ветви. Нужны read scopes каждого. Минимальный dependency-only
  read пока не реализован; разрешения автоматически не расширяются.
- Протокол защищает штатную запись и использованные source/catalog pins.
  Это не ОС-песочница для произвольной сырой правки JSON/индекса.
  Полнота произвольно подменённого raw catalog не доказана.
- Старое/imported готовое состояние без сохранённого события имеет historyPending:
  reader не выдумывает историю и не скрывает его как завершённое. Обычная
  авторизованная material-запись может сохранить готовые производные результаты.
- GUI имеет фиксированный direct-write owner. Произвольная навигация записи между
  владельцами, legacy Plan branch/gate/event editor и remote write не реализованы.
- Новый Gendocen Canon context, включая честное покрытие Requirement steps,
  не следует из доказанной completion-семантики и остаётся отдельным scope.
- Native picker, читаемость и весь установленный Windows/G2 сценарий не проверены;
  installed Tampermonkey не обновлён. Для следующего пользовательского прогона
  нужны проверенный гостевой доступ к той же разрешённой папке сессии и явно
  запущенный Helper. Новые mounts/ACL/туннели не предполагаются.
- Скрытие/понижение приоритета истории второстепенно и пока не реализовано.

Следующий крупный результат: подтвердить настоящий ручной browser/Windows путь
на доступных правах G2; затем отдельно расширять и проверять Gendocen coverage,
не объявляя его уже полным. Пользовательское acceptance и Stage 4 не подменяются
локальными тестами.
