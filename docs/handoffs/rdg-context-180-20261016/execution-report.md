## 1. Что появилось

### Документация

В существующем RDG-V7-WORKING-GRAPHS.md, §2/15, уточнены источники канонов и объяснений самих полей, различие definition/usage/value, условия вопроса, полнота и DRY. Здесь же находится технический контракт и примеры команд. Экранный план и модули Helper ссылаются на этого владельца; второй каталог терминов не создан.

Ссылочный материал допустим. Канон preparation=link-only показывает неполноту; наличие ссылки не означает готовую интерпретацию или полный список полей. Интерпретированный канон отдельно поясняет связь теории с конкретной R/option.

### Модель, общий список и запись

Добавлены optional поля schemaVersion=1:
- knowledgeSources и qualified sourceRefs;
- contextFields с объяснением и источниками;
- contextUses с purpose и необязательным when.allSelected;
- contextFieldRef и append-only contextAnswers в существующем Context owner.

Новый режим tools/rdg-context.py --fields получает список для графа либо набора: все объявленные поля, consumers/условия, актуальность, известные ответы/происхождение, неполнота и свободные записи для оценки. Скрытые альтернативы остаются в полном списке. Старый canon-directed lookup с --option-id сохранён.

record_context_answer создаёт/дополняет Context, set_context_contract обновляет метаданные, set_context_uses и set_canon_material аннотируют существующий материал с сохранением предыдущего содержания. Действуют revision/path/history/replay/recovery guards. Для нового принятого D package writer сохраняет разрешённый contextSnapshot в T1; изменение общего определения позже этот snapshot не переписывает.

Свободная запись сначала предлагается для смысловой оценки. Однозначный match можно явно связать с полем через mappingNote; исходный текст сохраняется. Автоматический семантический классификатор не добавлен, совпадение названия не считается доказанным соответствием.

### Viewer

- Кнопка «Поля контекста» и отдельная информационная карточка около главной R.
- На карте набора — общий список; «Просмотр контекста: вкл.» переводит клик по графу в инспекцию его полей. После выключения клик снова открывает граф.
- Общая карточка работает в обоих режимах.
- В списке видны объяснения со ссылками, общие ответы, поля сейчас/после выбора/с неизвестной актуальностью и неполнота.
- Открытие альтернативного графа не активирует его ветку.
- Информационный блок не становится R/D/member и не получает отдельного layout key. Он располагается над R, немного левее, и следует за её положением; независимо не перетаскивается.
- Источники/степень подготовки канона видны в его инспекторе. Ссылки открываются безопасно без исполнения текста материала.

### Учебные данные

Добавлены context-prepared и context-working, по три графа в каждом. Рабочий набор использует **те же определения и источники** context-prepared-root. В нём есть ранее полученный общий ответ, свободная запись о сроке, поле оценки вариантов и отложенное поле альтернативной ветки. Учебный D обозначен selected-in-example-only, не реальным commit проекта.

Каталог содержит 100 графов. Прежние 94 не мигрировали; старые examples, pins, source versions и working try-it сохранены.

## 2. Принятые при исполнении решения и DRY

PR-01, PR-03…06 выполнены в рамках команды пользователя исполнить v2. Для PR-02 выбран **PR-02A** после изолированного опыта: существующий Context достаточен как owner. PR-02B, отдельное хранилище, не выбран. Новых пользовательских Needs или самостоятельного веточного state store не введено.

Общий модуль tools/rdg-state.js используется Node CLI и встроенным Viewer; Python validator/index/writer вызывает тот же модуль через bridge. Генератор встраивает точный исходник. Для Python-пути контекстных полей нужен Node.js.

Definition, source и общий проектный ответ имеют одного владельца. Consumers сохраняют refs и свои purpose/условия. Derived index/stateGraphs/bundle и исторические T1 snapshots разрешены как производные/исторические представления, а не независимо редактируемые текущие owners.

Исходные плановые находки:
- **F-U-01 — owner-развилка:** resolved в scope этого пакета: fixture и реальный writer подтвердили PR-02A.
- **F-R-01 — ложная полнота link-only:** предусмотренный механизм устранён в проверенных данных: валидатор запрещает ложное complete, collector/Viewer передают incomplete. Полнота внешней теории всё равно не гарантируется.
- **F-R-02 — смысловое сопоставление:** риск остаётся управляемым. Нет молчаливого автоматического match; сначала оценка имеющихся записей, затем явная привязка с provenance либо узкое уточнение. Техническая поддержка PR-04 реализована; семантическая безошибочность ИИ не заявлена.
