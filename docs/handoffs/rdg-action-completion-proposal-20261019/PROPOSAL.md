## Candidate: завершение работы в графе закрывает шаг плана

**PR-PLAN-COMPLETION-01 — CANDIDATE, не committed.** Пользователь предложил
автоматически убирать выполненное из предстоящих шагов и сохранять историю.
Предложение связывает каждую запланированную единицу работы с Action в графе.
Это уточнение обсуждаемого workflow, не уже реализованная функция.

Предлагаемый путь:

1. Предстоящая работа имеет Action в графе, а шаг плана ссылается на него.
2. Человек или ИИ через разрешённую операцию явно записывает выполнение
   Action, с временем записи и доступным результатом/ссылками.
3. Общая история отражает сохранённое изменение и запись выполнения.
4. Представление «следующие шаги» автоматически исключает завершённую работу;
   исходный шаг и ссылки остаются доступны в истории. Повтор чтения не меняет факты.

Принятие Action и выполнение Action имеют разный смысл. Само изменение
описания или выбор Action не подтверждают выполнение. Достаточна обычная
разрешённая запись результата; три стадии подтверждения внешнего события
не вводятся для каждой завершённой работы.

В проверенной реализации Action.status содержит candidate/selected/rejected/
superseded. Writer прямо требует отдельный outcome contract для performed;
операции завершения и связанного автоматического закрытия Plan пока нет.
Нельзя просто добавить done к статусам выбора и объявить путь готовым.

Нужно решить правило для одного Action в нескольких steps/cases: завершение
работы должно закрывать соответствующие вхождения, не чужую повторную работу.
Существующий P2-AC-04 доказывает ссылки/зависимости, но не это поведение.
Цена подхода — больше Action-блоков и необходимость быстро создавать их из плана.
Скрытие/понижение приоритета истории остаётся второстепенным.
