# Граф-модель и план во времени — сверка семантики

**Источник:** прямое уточнение пользователя 2026-10-19 и его ответ о листовом
Action. **Статус:** определения и порядок работ обновлены; runtime не изменён.
**Stage 4 NOT ACCEPTED.** Это source review в той же среде, не independent acceptance.

Владелец определений — существующее
[руководство граф-модели](../../guides/RDG-V7-WORKING-GRAPHS.md), новый раздел
«Уточнение модели: граф, план во времени и выполнение — 2026-10-19».
[Текущий план](../../guides/RDG-CURRENT-EXECUTION-PLAN.md) задаёт порядок работ.

## Что уточнено

- Граф сам позволяет планировать варианты будущего без принятия предыдущих Actions.
- План во времени появляется при явном назначении времени и/или порядка.
  Создание Action не добавляет его в будущее расписание автоматически.
  Предыдущее утверждение ассистента об автодобавлении исправлено.
- Выполнение без предварительного размещения попадает прямо в историю выполнения.
  Не нужен фиктивный будущий шаг задним числом. Даты/порядок не выбирают вариант.
- Содержание создаваемого плана приложения и план действий граф-модели различаются.
- Подцели-разбиение, Requirements корректного выполнения и введение необязательной
  R имеют различную семантику и место challenge.
- Выбор реализации Action через альтернативные наборы подцелей раскрывается
  через R «решить, как выполнить Action».
- Достижение R определяется обязательными подцелями выбранного разбиения
  и выполнением выбранных Actions. Выполнение составного Action определяется
  достижением обязательных R его корректного выполнения; роли не смешиваются.
- Action без подцелей допустим по существующим критериям выделения сущностей.
  Его оценивают по собственному определению. Обязательный дополнительный
  узел результата не введён; пустой список не даёт автоматического успеха.

## Сопоставление с кодом

| Проверка | Фактическое состояние |
|---|---|
| Роли subgoal / method_correctness | Есть в CHILD_ROLES и selected Action children/link operations. |
| Action → R после выбора | INTRODUCES требует selected Action; parent R и DRIVES проверяются. |
| Предварительные R под непринятым Action | Текущий Action validator отклоняет INTRODUCES из candidate и OUTCOME_OF из Action. Legacy Option/OUTCOME_OF существует, но не доказывает эквивалентное поведение Action. |
| Создать подцель через отдельный Action | Graph API create_requirement сейчас создаёт DERIVES прямо из parent R. Это уточнение R, не требуемое причинное разбиение. |
| Выполнение Action и рекурсивная завершённость | performed не является допустимым статусом; writer сообщает, что нужен отдельный outcome contract. Полного расчёта нет. |
| Явные время/порядок | В существующей модели Temporal Plan есть sequence/timeConstraints и явные steps, но actionRef поддерживает Action; размещение R, общая история выполнения и результатный API не завершены. |
| Графовая история | Есть graph_changed и completed writer journals. Полноту всех UI/legacy путей и общую читаемую ленту это не доказывает. |

[Повторяемые source probes](source-probes.py) работают только в памяти.
[Результат](source-probes.json) фиксирует как разрешённый baseline, так и отказы.
Отказ требуемому новому сценарию — evidence gap реализации, не PASS её нового поведения.

## Открытые вопросы и Review Limitations

Точные формулировки трёх ранее заданных критериев создания сущностей в
проверенных исходниках не восстановлены. Найден WR-22 с формулой
(C1 OR C2) AND C3 для persistence, но его равенство критериям создания
не подтверждено. Критерии не переопределены. Personal Context недоступен
(поиск ответил disabled); новые формулировки по памяти не придуманы.

Листовой Action без разбиения допускается согласно ответу пользователя.
Конкретный формат сохранения результата и расчёта по определению остаётся
техническим дизайном; это не выбор обязательной дополнительной R.

Физическое представление отдельного Action введения необязательной R,
завершение повторных вхождений и разделение записи факта/вычисленного результата
ещё нужно определить. Новые типы рёбер и значения enum в код не добавлены.

Полная регрессия не повторялась для правки документации. Пять in-memory probes
не заменяют writer/API/Viewer acceptance. Предыдущие 71 PASS относятся
к shared-action checkpoint. Исторические строки P2 не повышены.
