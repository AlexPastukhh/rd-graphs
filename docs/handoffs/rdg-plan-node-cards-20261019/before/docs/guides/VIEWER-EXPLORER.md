**Новая пользовательская модель:** папка содержит один или несколько **полных графов**, определённых корневым Requirement (`rootRequirementId`). Открытие карточки не показывает файловые блоки и не требует `graph-set`. Полный граф строится по точным typed отношениям от корневой R, **не** обрезается административной папкой, использует актуальную `identitySpace` и не объединяет независимые корни. Связанные уточнения `DERIVES`/`same-requirement` сохраняют свою семантику и отдельные представления; они не «принятое разбиение». Ближайшая дочерняя R по клику открывает собственный **одноволновый** R-граф, даже если для отдельных R данные хранятся в общем JSON. Назад: R → полный граф → папка с восстановлением поиска/камеры.

**Два независимых измерения полного вида:** охват рабочего проекта «Принятое» / «Все ветви» и детализация «Только Requirements» (default) / «Показать всё» (R/D/Options на доступную глубину). Для готового графа потенциальные ветви видны сразу. В `Все ветви` видны и user-authored бумажные потенциальные R нескольких волн, без принятого D, и подготовленные варианты. В подробном виде доступны D и Options, даже если они ещё не вводят R. Источник/основание каждой причинной связи доступен в инспекторе. Переключатели не изменяют принятие или данные.

**Старые одиночные файлы:** пять legacy-графов без `identitySpace`/`rootRequirementId` (включая рабочий `try-it`) сохраняют прямые карточки в папках и открываются локально; они не объявляются полными причинными графами до явного задания точной идентичности. Оригинальные файлы не переписываются ради нового UI.

**Папки/метаданные:** `graphs/catalog.json` и source `graph.json`; derived индекс содержит `fullGraphs` вместо `graphSets`; `rdg-catalog.py` проверяет безопасные пути и раскрывает папки, локальный Loader читает только разрешённые `graph.json`. Подключённый prepared материал не считается принятым проектом. Недоступные источники обозначаются как неполнота; Viewer не угадывает дополнительные R по схожему названию. Физический граф может быть сложнее одной волны — локальная R ограничивается лишь видимостью.

**Исторический Viewer 1.8.0** показывал граф из блоков `graph.json`, объединённых вручную в `graph-set.json`. После прямой миграции это не действующее пользовательское представление. Версия установленного Tampermonkey/Windows Loader отдельно не подтверждается тестами кода в Docker.


## Автосохранение расположения

1. Один раз подключите существующий общий файл graphs/layouts.json и разрешите запись. При первом подключении после перемещения предлагается сохранение в файл; выберите именно файл текущего проекта.
2. Перетащите блок и отпустите его. После паузы 650 мс Viewer записывает координаты и проверяет результат чтением.
3. Дождитесь «Сохранено». Следующие правки во время записи автоматически поступают в следующую запись. Переход к другому графу или в проводник не теряет адрес команд.

Перемещения во время одного drag не вызывают файловую запись на каждом mousemove. Короткая серия завершённых правок объединяется. Статус относится к общей очереди всех изменённых графов; «Сохранено» означает подтверждённую запись последней актуальной команды, а не только первой из серии.

| Статус | Значение / действие |
| --- | --- |
| Для автосохранения подключите файл | Общий файл ещё не подключён |
| Изменения не записаны — подключите файл расположений | Блок перемещён, но общий файл ещё не подключён; это не подтверждение записи |
| Ожидает сохранения | Есть очередь изменений |
| Сохранение… | Идёт запись и read-back |
| Сохранено | Последняя актуальная правка подтверждена в файле |
| Нет доступа к файлу | Требуется явное восстановление права на запись |
| Ошибка записи | Черновик сохранён; повторите запись после устранения причины |
| Конфликт версий | Внешнюю версию не заменяем; сохраните копию черновика и перечитайте файл |
| Восстановлен локальный черновик | После reload требуется явное «Записать сейчас» |
| Автосохранение приостановлено | Очередь ждёт возобновления или явного сохранения |

В меню «Расположение»: «Записать сейчас», выбор файла, экспорт, восстановление автоматической расстановки, отмена правок и пауза. Сброс координат сохраняется автоматически по тем же правилам. Экспорт скачивает отдельную копию; он не подтверждает запись в общий файл.

Браузер запоминает настоящий файловый дескриптор в IndexedDB. При reload проверяется доступ; автоматическая запись не открывает запросы разрешения. Пользователь подтверждает право отдельным действием. Если File System Access API недоступен, работает явно обозначенный режим локального черновика и экспорта.

Каждая вкладка пишет отдельный журнал черновика в localStorage и, при доступности, IndexedDB. Сохранение и отмена правок удаляют только журнал этой вкладки. При доступности Web Locks браузер удерживает владельца журнала до закрытия документа: reload восстанавливает свой журнал, а дублированная вкладка получает нового владельца. Без Web Locks новый документ получает новый журнал; восстановление прежнего доступно явно через «Расположение → Восстановить черновик…». Там же доступны журналы других вкладок и прежнего формата. Восстановление копирует выбранный журнал; исходник не удаляется автоматически. Черновик прежнего формата автоматически импортируется один раз для каждого его содержимого; после сохранения или отмены он остаётся доступен только для явного восстановления. Если текущие правки не сохранены, сначала сохраните или отмените их. Старый журнал может содержать прежние координаты: выбор восстановления остаётся явным. Его восстановление не заменяет молча более новую файловую базу. Если локальное хранилище браузера запрещено, восстановление после закрытия не гарантируется. Во время выгрузки вкладки нельзя гарантировать завершение асинхронной записи; несохранённые команды вызывают предупреждение. Нормальный путь — дождаться «Сохранено».

## Пользователь и ИИ: общий формат

UI и CLI используют один rdg-layout-core.js, встроенный в Viewer без изменения исходника. Существующие ключи [identitySpace, slug] и [identitySpace, slug, rootRequirementId] сохранены.

**Ключ полного графа:** `layoutCore.graphKey(identitySpace, 'full-' + rootGraphSlug, rootRequirementId)`. Это отдельный JSON-массив ключа расположения, не пересекающийся с прежними локальными ключами отдельных R. Узлы full layout адресуются **Requirement ID**, а в подробном виде технические D/O получают отличимые производные ID. Прежние сохранённые позиции *файловых блоков* graph-set не интерпретируются как координаты Requirements. Оставшийся исторический ключ в `layouts.json` не влияет на новую расстановку и не удаляется автоматически. `set_positions`/`clear_layout`, revision, read-back, file access и conflict guards не меняются.


## Последовательная запись UI / CLI

Внутри Viewer работает один writer. Доступные Web Locks сериализуют подключённые вкладки одного origin; устаревшая база отклоняется. CLI имеет свою блокировку. Общего атомарного исключения между браузером и CLI по-прежнему нет.

Для работы ИИ: дождитесь «Сохранено», включите паузу, выполните запись CLI, перечитайте файл в Viewer, затем возобновите автосохранение. При конфликте автоматические повторы останавливаются; черновик остаётся для экспорта или отмены.

Между последней проверкой и close остаётся окно внешней записи. Новые серверы, tunnels и mounts для устранения этого ограничения не добавлены.

## Источники каталога и переиспользуемые функции

tools/rdg-catalog.py рекурсивно обходит только подключённый graphs. Служебные каталоги, source-versions, snapshots, generated и symlink-директории не обходятся. Ссылки манифеста проверяются отдельно; выход за корень и symlink-источники отклоняются.

- folder.json необязателен: schemaVersion=1 и presentation с title/description. Без него показывается имя директории.
- graph.json описывает отдельный R-граф. Необязательные catalogSlug и presentation задают устойчивый slug и отображение.
- `graph-set.json` больше не используется текущим каталогом: исторические манифесты сохранены только в проверенной резервной копии. Текущий `fullGraphs[]` вычисляется по `rootRequirementId` и доказанным связям, а не по списку членов набора.
- graphs/catalog.json сохраняет устойчивые slug и presentation, задаёт актуальные папки. Шесть старых файлов Context физически перемещены в `graphs/examples/archive/`; исторические источники и pins не переписываются при просмотре.
- graphs/index.json и tools/rd-graph-data.js — производные. После правки источников выполните python3 tools/graph-index.py.

Presentation: title, description, usage=ready|working, exampleOnly, archived. Usage не определяет права, принятие D или доказанную применимость готового материала. Старые графы без метаданных остаются доступны с неизвестным назначением.

**Границы полного графа:** совпавший `identitySpace` сам по себе не объединяет независимые корни. Обход начинается от конкретной root R и требует подтверждённой причинной связи; продолжения могут лежать вне папки. Независимые полные графы разрешены в одной папке. `DERIVES` — особое уточнение, не выбранная под-R. Готовая 2D-библиотека содержит десять самостоятельных заготовок; ранние мини-примеры и старые комплекты находятся в архиве.

`tools/rdg-catalog.js` обслуживает нормализацию, поиск и папки, а `tools/rdg-root-projection.js` строит полные графы Requirements; оба используются Viewer. Карта полного графа — проекция существующих typed source relations, а не новый записываемый владелец D, R или parent-child. Старые `buildGraphSetView`/`projectGraphSet` и правила о members относятся к историческому Viewer 1.8, не к текущему интерфейсу.

Просмотр вложенного пути не даёт права записи модели. Package writer допускает нормализованные вложенные graph.json только внутри workspaces, сохраняя readOnly, guards, recovery, read-back и запрет symlink/выхода из корня. Остальные папки остаются источниками чтения. Координаты read-only моделей разрешено сохранять отдельно от их содержания.

## Проверка и доставка

Основной тестовый набор: node --test tests/*.test.cjs tools/rd-graph-viewer-smoke.test.cjs.

Адресные сценарии: tests/rdg-autosave-explorer.test.cjs и tests/rdg-catalog-sources.test.cjs. Они покрывают очередь, паузу, конфликт, потерю разрешения, восстановление, ключи наборов, CLI, произвольные папки, стабильные ID, пути, symlink и вложенную запись workspace.

Браузерные сценарии через tools/rdg-visual-test.sh:
- tests/visual/viewer-navigation-170.cjs — колесо/модификаторы, текущая и альтернативная ветки, тональные состояния, подписи у целей и плотная сцена, настоящий OPFS save/reload, desktop/mobile.
- tests/visual/viewer-screenshots.cjs — основной сценарий, UI/CLI в одном тестовом JSON, desktop/mobile.
- tests/visual/viewer-layout-regressions.cjs — прежние регрессии групп, геометрии, local levels и native Web Locks.
- tests/visual/viewer-autosave-native.cjs — настоящий FileSystemFileHandle / OPFS в отдельном профиле Chromium, автоматическая запись после mouse drag, read-back, восстановление дескриптора и черновика, автосохранение сброса.

OPFS-проверка использует файловое хранилище изолированного браузера, не graphs/layouts.json пользователя. Windows picker и установленный Tampermonkey ею не проверены. HOST G2 вернул PermissionDenied при адресной проверке Windows-пути исходника; этот отказ не обходился.

Для доставки в установленный Viewer обновите внешние зависимости Local Loader в Tampermonkey и перезагрузите ChatGPT. Затем один раз подключите graphs/layouts.json. Значок «Сохранено» после перетаскивания подтверждает native-запись в выбранный пользователем файл; один лишь номер версии этого не доказывает.

## Исправления 1.6.1

По результатам независимой проверки 1.6.0 исправлены PR-01…04 (R-RDGEXPLORER-20261016-01/v1). Вкладки больше не используют один общий ключ черновика; восстановление доступно в меню. Первое перемещение без подключённого файла меняет видимый статус на «Изменения не записаны». «Сохранено» по-прежнему требует записи и обратного чтения последней команды.

Имена папок с буквальными `#` и `%` принимаются общим каталогом. Чтение файлов кодирует каждый сегмент URL, поэтому эти символы не становятся fragment или escape-последовательностью. Защита от абсолютных путей, `..`, обратных слешей и выхода через symlink сохраняется.

Если внутри папки набора есть граф, не указанный в members, проводник оставляет обычный путь папок к нему. Такой граф не становится участником набора. Внутренние папки, нужные только участникам набора, по-прежнему скрыты из обычного списка.

PR-05 (общий атомарный writer UI/CLI) не реализован. Для UI и CLI сохраняется последовательный порядок: дождаться записи, приостановить UI, выполнить CLI, перечитать файл и возобновить работу. Проверки в Repo не подтверждают доставку в установленный Windows Tampermonkey.
