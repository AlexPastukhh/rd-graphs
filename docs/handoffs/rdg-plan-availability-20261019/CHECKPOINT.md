## Результат

Plan owner после долговечной записи store и owner index сохраняет отдельную
квитанцию `availableBy` для версии. Она связана с `sourcePath`, revision и
`recordDigest`. Подготовленный journal остаётся до записи квитанции.
Recovery при сбое до квитанции завершает Plan/index и ставит консервативное
время; при сбое после квитанции сохраняет её время. Повтор транзакции не
переписывает квитанцию; повреждённая квитанция закрывает временной запрос.
Старое поле Plan `recordedAt` остаётся неизменным по смыслу: оно ставится
перед долговечной записью.

Read-only resolver использует квитанцию для `knownAt` даже у **последней**
версии Plan. Для старой версии без квитанции сохраняется свидетельство через
следующую защищённую правку. Для RDG по-прежнему нужен завершённый v2 journal
с after-образом и временем после записи Graph. Временной cutoff ограничивает
доступность закреплённых источников, не выбирает весь применимый контекст.
`effectiveAt` и исторический Gendocen runtime остаются открытыми;
`twoTimeAsOfResolved=false`, `historicalT1KnowledgeVerified=false`.
[Контракт и пример](../../guides/RDG-EXACT-HISTORY-PILOT-P2.md).
