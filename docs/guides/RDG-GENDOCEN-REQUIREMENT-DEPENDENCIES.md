# RDG → Gendocen: действующий контракт зависимостей

> **СТАТУС: ДЕЙСТВУЮЩИЙ КОНТРАКТ GENDOCEN.** Источник общих понятий и прав: [RDG-ACTIVE-CONTRACT](RDG-ACTIVE-CONTRACT.md). Предыдущий протокол внедрения оставлен [в архиве](RDG-GENDOCEN-REQUIREMENT-DEPENDENCIES-HISTORY.md).

Этот документ описывает отдельную подсистему Gendocen для прежних owners. Native политики, `review.required` и карточки Decision-инвалидации описаны в [текущем контракте](RDG-ACTIVE-CONTRACT.md#политики-зависимостей); их проверка не доказывает состояние внешнего engine.

## Раздельные владельцы

Graph хранит настоящие Requirements, Actions, каноны, причинные отношения и свои события. Plan хранит независимые версии размещений R/A. **Gendocen хранит собственные dependency baselines, engine receipts, diffs и историю проверок**; Gendocen не является Graph writer и не создаёт новые R или Actions. Планирование не доказывает завершение, а зависимость не заменяет авторизованную проверку бизнес-истины.

## Что означает статус

Если после авторизованного изменения R фактические данные расходятся с сохранённым baseline подписанной зависимости, Gendocen может пометить затронутые A/R как **`review_required`**. Это означает **«нужно пересмотреть»**. Не означает автоматической ошибочности Action, пересмотра выбранного способа, отмены исполнения, завершённости или принятой новой версии канона. Подписанное review-подтверждение — отдельное действие; отсутствие новой проверки не считается успехом.

Источники привязок: реальные Graph owner IDs и typed links, канонические зависимости и QRPE, конкретные `checkRequirements`/`dependsOnRequirements`. У альтернативного Action может быть собственная зависимость, даже если он не selected. Движок не сканирует все неавторизованные или неизвестные внешние проекты и не выводит скрытые ссылки по общему названию.

При refresh существующего engine-проекта bridge сначала сверяет `identitySpace` и состав `graphFiles` с manifest. Смена владельца или состава scope отклоняется с `PROJECT_OWNER_CLOSURE_CHANGED` **до записи** конфигурации и проекций входов. Отклонённая перепривязка сохраняет прежний engine-проект без изменений; она не является способом расширить авторизацию.

## Живой режим и опубликованный снимок

Авторизованный Helper запускает refresh Gendocen **после успешного commit Graph writer**. Если изменение прошло другим writer вне Helper, последующий refresh / чтение engine должно выполняться отдельно — это не автоматическая нотификация. При ошибке engine Graph commit не превращается в rollback semantic truth; UI сообщает о необходимости синхронизации.

Если file/Helper отсутствуют, Viewer может отобразить только **заранее опубликованный read-only снимок** из `tools/rdg-published-owners.json`, включённый в `tools/rd-graph-data.js` при **совпадающей версии/identity Graph и Plan**. UI обязан маркировать, что это не live refresh; с такого просмотра нельзя изменить status, выполнить Action или подтвердить Gendocen. Когда snapshot недоступен или stale, не подставлять ложный ноль зависимостей. Живой авторизованный Helper остаётся предпочтительным источником.

## Практическая проверка

Конкретный учебный сценарий с действительно переформулированной R и индивидуальными affected Actions см. в [описании учебного Graph](RDG-LIVE-TEACHING-WORKSPACE.md). Запуск/публикация и безопасные права находятся только в [операционном регламенте](RDG-OPERATIONS.md). Реальные тесты: `tests/rdg-requirement-gendocen.test.py`, `tests/rdg-active-example.test.cjs`, `tests/visual/rdg-active-example.cjs` и `tests/visual/rdg-offline-published-owners.cjs`. Stage 4 **не принята**; установленный пользовательский Viewer не подтверждён.

Проверки bridge разделены на инвентаризацию связей и сценарии настоящего движка во временных проектах:

| Проверка | Ожидаемое поведение |
| --- | --- |
| Цепочка R → A → R → A, явные ссылки канона, альтернативный Action | Зависимости сохраняются и наследуются по действующим правилам |
| Архивная связь, одинаковые названия без ссылки | Не создают зависимость |
| Межграфовая проекция и квалифицированная ссылка канона | Сохраняют настоящего owner |
| Цикл, отсутствующая R, неоднозначный canonical owner | Обход завершается без зависимости на себя; некорректные ссылки отклоняются |
| Постороннее изменение R и повторный refresh | Сохраняют `valid` и прежние receipt IDs зависимых проверок |
| Изменение настоящего входа R | Затронутые selected и альтернативные Actions требуют review без автоматического принятия или исполнения |
| Смена identity или расширение scope существующего проекта | Отказ до записи; файлы проекта остаются побайтно прежними |

Эти проверки покрывают существующую модель. Правила зависимостей будущих подключаемых модулей и полная приёмка этапа остаются в [плане разработки](RDG-DEVELOPMENT-PLAN.md).


## Уточнённый core-профиль

Для coreModel: rdg-core-v1 bridge инвентаризирует реальные источники R, A и Context, а также применимые Canon через рабочую связь CANON_FOR. INTRODUCES даёт настоящий источник A выходной R; транзитивный обход включает все объявленные рабочие цепочки и завершается при цикле. Локальные условия канона не получают внешние рабочие refs, пояснительные Info/Evidence links и текстовые упоминания не становятся зависимостями. Содержательные проекции всех закрытых объектов доступны по nodesById; review/assessment/QRPE административные заметки не создают бесконечного повторного invalidation. Новые/снятые связи пересобирают подписки при refresh.

Graph core самостоятельно помечает необходимость проверки известных локальных зависимых при принятой правке. Gendocen имеет собственные review baseline/receipts и может потребовать отдельной проверки своих входов. Ни один из этих статусов не доказывает ложность R, непригодность A или фактическое выполнение. Область, права и отсутствие внешнего evidence сохраняют прежние ограничения. Соединение workGraphs внутри одного core store не означает скрытую перепривязку engine к чужому физическому owner.


Origin выходной R является содержанием рабочей связи INTRODUCES. Его явное изменение через core_output_origin меняет содержательные версии затронутых R/A и требует пересмотра зависимых; оно не создаёт прямую DERIVES и не выдумывает исполнение. Блокировки завершения вычисляет Graph core с учётом выбранного A и роли origin, отдельно от Gendocen review baseline.
