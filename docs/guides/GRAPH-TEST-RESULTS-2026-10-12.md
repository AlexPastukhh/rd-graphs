# Результат первого прогона графовых тестов

Дата: 2026-10-12. Объект: только Requirements–Decisions graph (файл/семантика/просмотр/рабочие сценарии).
Канонический пример `graphs/examples/example/graph.json` не изменялся. Исходный просмотрщик также не изменялся в этом прогоне.

## Запуск

```bash
cd /workspace/repos/rd-graphs
node --test tests/graph-data.test.cjs tests/graph-viewer.test.cjs tests/graph-scenarios.test.cjs
node tests/graph-gap-probes.cjs
```

Среда: Node.js + модель DOM (не реальный браузер). `graph-scenarios.test.cjs` проверяет только структуру и локальное сохранение **тестовой копии**, а не исполнение промптов и запись через Fortis Repo.

## Автоматизированные результаты

- 25 acceptance-тестов: **24 PASS, 1 FAIL**.
- 11 data-тестов: PASS, включая контроль ID, dangling edges, отсутствие parent, невалидный schemaVersion, 500/501 узлов.
- 10 тестов просмотрщика: 9 PASS, 1 FAIL. Работают загрузка, выбор, поиск, pan/zoom (Fit/zoom), повторное чтение, ошибка JSON, переключение графов.
- 4 упрощённые структурные пробы сценариев: PASS (путь R→D→R→D→R→R, решение без под-R, контекст для D, read/write/read копии).
- 8 gap-probes: во **всех восьми** просмотрщик принял вход, который нарушает или не выражает нужную рабочую семантику. Это не PASS приёмки.

## Findings

| ID | Приоритет | Фактический результат | Следующее действие |
| --- | --- | --- | --- |
| F-G-01 | P0 | `INTRODUCES.parent=C-001` принят, хотя parent должен быть Requirement | Проверка parent kind и согласованности parent с порождающим D |
| F-G-02 | P0 | `DRIVES` R→R и `INTRODUCES` R→R допускаются | Контракты направления и типов связей |
| F-G-03 | P0 | Цикл разбиения R→D→тот же R принят | Защита от циклов именно в цепочке разбиения |
| F-G-04 | P0 | D со статусом proposed имеет неотмеченные как candidate `INTRODUCES` | Определить и проверять статус кандидатных ветвей; не переносить в committed автоматически |
| F-G-05 | P0 | `revision: "not-an-integer"` и `events: {}` принимаются | Версионированная схема + проверка структуры событий |
| F-G-06 | P1 | Произвольный тип связи `WHATEVER` принимается | Определить расширяемый словарь/контракт типов, не навязывать закрытый список без решения |
| F-V-01 | P1 | Пустой граф принят, но вычисляется `translate(Infinity Infinity) scale(0.12)` | Исправить layout/fit для zero nodes и оставить регрессионный тест |
| F-W-01 | P0 | Нет реализованного атомарного updater/merge/revision guard | Разработать механизм безопасного изменения графа, затем прогнать S12–S18 |
| F-W-02 | P0 | Нет сквозного механизма вызова промпта → смысловая дельта → сохранение → статус | Подключить основной/специализированные промпты и воспроизвести S01–S11, S15 |

Первым восьми gap-probes соответствуют F-G-01–06; несколько проб подтверждают один и тот же класс проблемы.

## Что ещё не проверено

- S01–S11: сценарии с ChatGPT/Planning Helper по фактическому планированию, принятию D, делегации, QRPE, статусу — **BLOCKED** отсутствующим исполнителем операций; в тестах проверена только возможность представить несколько цепочек в JSON.
- S12–S14, S17–S18: атомарность, обновление revisions, конфликт двух сессий, no-op, отмена/замена D — **BLOCKED** отсутствующим updater.
- S15–S16: поведение реальной новой сессии и загрузка файла после записи через Fortis Repo — **NOT_RUN** (есть только локальный тест round-trip копии и эмуляция папки).
- V01–V10 в настоящем браузере, включая визуальную читаемость больших/широких графов — **NOT_RUN**.
- G10–G11 с shared D/делегацией в реальной системе — **NOT_RUN**, отдельные fixtures ещё нужны.

## Порядок следующей проверки

1. Исправить и покрыть F-V-01 (пустой граф), F-G-01–05 (семантическая целостность).
2. Выбрать способ фиксации proposed/committed дочерних R, единое понятие revision и минимальную структуру events.
3. Реализовать безопасный updater с проверкой текущей revision, атомарностью и повторным применением без дублей.
4. Прогнать сквозной сценарий S01→S02→S03→S11→S15→S16 на тестовой папке: начать цель, принять разбиение, продолжить, открыть новую сессию, обновить и увидеть результат.
5. Проверить S08→S09→S13→S18: пересмотр на новом контексте, альтернативы, конфликтующие правки, сохранённая история.
6. Выполнить ручную браузерную приёмку с читаемыми скриншотами/наблюдениями для V01–V10.

Главная граница результата: работоспособность viewer в эмуляции **не доказывает** надёжность постоянного ведения графа; пока это просмотрщик JSON и договорённость о ручном обновлении.
