# RDG Viewer: один уровень R, группы и расположение (реализовано в 1.7.0; локальный R-view действует в 2.0.0)

## Граница графа

Для любого графа с корневой R Viewer показывает её варианты или ответ D и **один уровень под-R**. Это правило действует для каталога, ручного JSON, архивных примеров и 2D. У под-R не раскрываются её собственные ответы и дальнейшие R. Нажмите R со значком перехода: точное продолжение из каталога откроется отдельным файлом; если его нет, Viewer откроет локальный уровень из уже загруженных записей, с этой R в корне. Назад возвращаются положение камеры, открытые списки и координаты родителя.

Локальный уровень не создаёт новый owner, Requirement или решение и не переписывает source JSON. Обновление каталожного файла сохраняет текущую корневую R локального уровня; возврат к уровням того же обновлённого файла читает обновлённые записи. Если R удалена из новой версии, загрузка отклоняется и прежний вид сохраняется.

Для старых файлов без rootRequirementId остаётся прежнее распознавание корня: первая R с DRIVES, не введённая INTRODUCES, либо единственная R. Набор записей без распознанной корневой R не превращается в выдуманную иерархию. Для нового дерева задавайте rootRequirementId явно. Флаг view.requirementDepth: 1 больше не нужен для включения ограничения.

**Граница применяется к отображаемому графу, а не к переписыванию старого хранилища записей.** Исходные JSON владельцев сохраняют свои записи и историю, в том числе записи следующих уровней. Отдельные файлы продолжений — проекции тех же ID через `projectionOf`; они не создают новые нормативные R или D. Старые владельцы, preparedSource и T1 не мигрировали. Это сохраняет проверяемое происхождение и исторические pins.

Подготовленный набор теперь имеет 6 представлений. Добавлены отдельные уровни RF-2 и RS-2. Рабочий набор имеет 10 представлений: добавлены соответствующие подготовленные продолжения, `reference-mixed-contextual-split` с корнем R-COMP и `reference-mixed-change-log` с корнем R-OTHER. Начальный R0 заканчивается на R-COMP; D-A и его под-R показаны в графе R-COMP. Ссылка DERIVES — уточнение R, а не выбранное D. Ссылка на ту же R также не доказывает дочернее происхождение.

Карты различают сплошную линию выбранного D, штрихи потенциального пути O и точки уточнения/той же R. Число представлений вычисляется из набора. Исторический `preparedGraphSetReference` по-прежнему описывает прежнее учебное сопоставление четырёх исходных файлов, а не фактически выполненный новый импорт. `candidate-unverified` не менялся.

## Группы

Collection содержит только ID Requirements. Ссылка на option или D отклоняется до загрузки графа. Списки из одного-двух R показаны сразу, без узла группы.

Клик по большей группе убирает её блок и показывает входящие R. Их продолжения остаются за границей уровня. Уже видимые узлы и камера не перемещаются; новые R появляются с коротким затуханием, если разрешена анимация. Кнопка **«Свернуть в группы»** сворачивает все открытые группы. Она не прячет малые списки, которые не требовали раскрытия. Это операции представления, не записи в модель требований. Открытие/закрытие всех вариантов также сохраняет камеру и уже видимые узлы. Для общего обзора используйте «Показать всю схему».

## Перетаскивание и сохранение

В Viewer 1.6.0 после подключения общего graphs/layouts.json расположение автоматически записывается после завершения drag и короткой паузы. Дождитесь «Сохранено»: статус появляется только после read-back последней актуальной команды. Команды, поступившие во время записи, автоматически сохраняются следующим проходом; переход между графами или в проводник не меняет их адрес.

«Показать всю схему» меняет только камеру. Меню «Расположение» содержит «Записать сейчас», паузу, выбор файла, экспорт, сброс автоматической расстановки и отмену правок. Сброс также сохраняется автоматически. Без доступа к файлу изменения остаются явно обозначенным черновиком. Экспорт — отдельная копия.

Файловый дескриптор и черновик восстанавливаются через браузерное хранилище при доступности. Восстановленный черновик требует явного продолжения, чтобы не перекрыть новую файловую базу. При конфликте автоматические повторы останавливаются. UI и CLI используют последовательную запись; общего атомарного CAS между ними нет. Перед внешней записью включите паузу, после неё перечитайте файл и возобновите очередь.

Полное описание статусов, нового проводника, формата наборов, ключей координат графа графов и ограничений: [VIEWER-EXPLORER.md](VIEWER-EXPLORER.md). Разделы проверки 1.5.0/1.5.1 ниже — исторические результаты прежних этапов.

## Единый слой для пользователя и ИИ

Канонический код команд: `tools/rdg-layout-core.js`. Он проверяет документ, применяет команды без мутации исходника и фиксирует следующую ревизию. Viewer содержит автоматически встроенную копию **того же исходника**, а CLI импортирует модуль напрямую. Тест проверяет побайтовое совпадение. После изменения модуля выполните `python3 tools/build-rdg-layout.py`.

Общий документ:

```json
{"schemaVersion":1,"revision":1,"layouts":{"[\"identitySpace\",\"graph-slug\"]":{"positions":{"R-ID":{"x":60,"y":300}}}}}
```

Ключ главного уровня включает identitySpace и стабильный slug графа. Для локального продолжения он содержит третий элемент — rootRequirementId: `["identitySpace","graph-slug","R-ID"]`. UI и CLI используют один формат. Расстановки разных корней одного файла не смешиваются. Координаты задаются в пространстве схемы и не зависят от масштаба окна. Отрицательные координаты допустимы; маршруты и подписи работают в том же пространстве. «Показать всю схему» учитывает узлы, линии и подписи. Нечисловые и чрезмерные значения отклоняются. Каноны и свёрнутые группы имеют стабильные view-only ID `__canon__<optionId>` и `__collection__<collectionId>`. Координаты этих узлов также находятся в данных, не в JS.

Команды: `set_positions` объединяет координаты перечисленных узлов с прежними; `clear_layout` удаляет сохранённую расстановку данного графа. Применение — черновик; фиксация увеличивает revision. Другие графы не перезаписываются.

Для ИИ и CLI сначала прочитайте ревизию:

```bash
node tools/rdg-layout-cli.cjs --show
```

Подготовьте JSON команды, например:

```json
{"type":"set_positions","graphKey":"[\"rdg-example-prepared-v7\",\"reference-prepared-planning-tree\"]","positions":{"R-PLAN":{"x":60,"y":300}}}
```

Затем укажите **прочитанную** ревизию, например 1:

```bash
node tools/rdg-layout-cli.cjs --expect-revision 1 --commands-file /path/to/commands.json
```

CLI проверяет identitySpace, граф, необязательную локальную корневую R, ID узлов, координаты и ревизию, записывает JSON атомарно и читает результат обратно. Для штатного `graphs/layouts.json` он также пересобирает индекс/bundle. `--file` позволяет проверить тот же процесс на отдельном тестовом файле. Начальная компактная расстановка подготовленного примера введена именно этой командой, в `graphs/layouts.json` revision 1. В Viewer нет координат этого примера.

Программный интерфейс открытого Viewer:

```js
const layout = document.getElementById('rdg-viewer-root').rdgLayout;
layout.apply({type:'set_positions',positions:{'R-PLAN':{x:60,y:300}}});
await layout.save();
```

`layout.graphKey()` возвращает ключ открытого графа; `getDocument()` — копию документа. `attachFile(handle)` подключает стандартный FileSystemFileHandle, `load(document)` читает документ без несохранённых правок. Программный интерфейс использует те же команды и сохранение, что кнопки и перетаскивание. Он не выдаёт права файлового доступа автоматически.

## Историческая навигация на карте файлов (Viewer 1.7.0, superseded в 2.0)

Колесо — вертикальная прокрутка; Shift + колесо — горизонтальная; Ctrl + колесо — масштаб относительно курсора. Камера не меняет координаты и не ставит команды сохранения. Подписи общего renderer размещаются у целей и учитывают другие блоки/подписи, включая обратные и вертикальные связи после drag.

Рабочий граф графов показывает текущую ветку и контекст; «Показать альтернативы» добавляет возможные ветки с отдельным тоном и явной пометкой. Полный контракт происхождения, неизвестных путей, готовых наборов, фокуса и возврата — в [VIEWER-EXPLORER.md](VIEWER-EXPLORER.md). Формат и общий слой координат не изменились.
