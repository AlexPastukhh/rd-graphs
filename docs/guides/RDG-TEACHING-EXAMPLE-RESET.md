# Пересоздание учебного Graph с нуля (candidate-v6)

## Граница удаления

В папке **«Примеры»** Viewer публикуется рабочий учебный граф `requirements-dependencies-demo`. В каталоге он расположен в `examples`, а его *авторитетный Graph owner* технически находится в `graphs/workspaces/requirements-dependencies-demo/graph.json`: это обязательный путь для штатного Graph writer. Дублирующего `graphs/examples/*/graph.json` новой модели нет. Архивные `graphs/examples/**` старой модели остаются неактивными, не пишутся и не участвуют в reset.

**История учебного примера пересоздаваемая**, но это не общая возможность переписывать прошлое. Обычные рабочие Graph owners сохраняют журнал без удаления. Для reset нужен точный владелец в `tools/rdg-resettable-examples.json`, совпадение `identitySpace`, `purpose`, Graph/Plan владельцев, расположение именно в каталожной папке `examples` и отдельное повторное подтверждение имени. Чужие Plan refs, общие или незавершённые Graph-транзакции, symlinks и неизвестные цели блокируют reset.

При сбросе **полностью** заменяются принадлежащие одному учебному примеру:

- Graph с узлами и событиями; все его принятые Graph writer journal files;
- собственный Temporal Plan owner со всеми прежними версиями;
- собственное Gendocen project state с baselines, receipts и engine history;
- опубликованный производный read-only snapshot. Он не является источником истины.

Сначала данные этого владельца временно резервируются в скрытой директории для отката. На успехе предыдущая история **удаляется физически**, а не маскируется `inactive`/`archived`. Резерв хранится в стабильной скрытой `.rdg-example-reset-*` папке, которая **не удаляется автоматически** при аварийном завершении или гибели процесса; незавершённый резерв блокирует повторный запуск до ручного восстановления. Удаление резерва допускается только после проверенного успеха/отката. При ошибке до резервирования живые файлы **не трогаются**. На ошибке после резервирования текущий owner восстанавливается из неё. Сама операция не может применяться к обычным рабочим графам. **Не запускать одновременно с подключённым Helper или другим редактором.**

## Команды

Из корня проекта:

```sh
# Без изменений, только список разрешённых для полного пересоздания учебных примеров.
python3 -B tools/rdg-rebuild-teaching-example.py

# Только для заранее разрешённого примера: полная очистка и повторный API-build.
python3 -B tools/rdg-rebuild-teaching-example.py \
  --reset requirements-dependencies-demo \
  --confirm requirements-dependencies-demo
```

`--reset try-it`, произвольные slug и любые обычные рабочие проекты отвергаются. Добавить другой пример можно только явно: зарегистрировать owner/identity/Plan/Gendocen/штатный builder в отдельном allowlist и обеспечить собственные проверки. Наличие слова «пример» в названии не разрешает сброс.

Сборщик `tools/rdg-build-working-example.py --apply` всегда **создаёт новый**, а не перезаписывает существующий Graph. Он начинает с единственной корневой R, затем записывает каждый Action, выбор, введение подцелей, переформулировку через реальные авторизованные Graph API операции, создаёт первоначально пустой Plan, затем три CAS-размещения, Gendocen baselines и реальные review receipts. Он не сочиняет факты `action_executed`/`requirement_achieved`. В Viewer история строится по новому Graph writer journal + Plan owner versions и Gendocen receipts; старые, несвязанные с новым построением события не сохраняются.

Точные счётчики текущего учебного Graph/Plan/Gendocen и история находятся **только в** [актуальном учебном примере](RDG-LIVE-TEACHING-WORKSPACE.md) и проверяются автоматически по настоящим owner файлам. Здесь описана **процедура**, а не ещё одна копия состояния графа.

## Типы блоков при пересборке

Текущий учебный builder создаёт базовые R/A. Reset не включает дополнительные типы и не выдаёт writer rights. Общие правила типов, owner-scoped расширений и авторизации находятся в [действующем контракте](RDG-ACTIVE-CONTRACT.md); пересборка им подчиняется. Ограничения самого reset и его allowlist остаются в этой инструкции.

## Контроль

`tests/rdg-node-type-policy.test.py` проверяет базовые типы и разрешения дополнительных. `tests/rdg-active-example.test.cjs` проверяет физически чистую новую историю и расположение в каталожной папке «Примеры». `tests/visual/rdg-graph-scope.cjs` проверяет полный обзор Requirements и локальные графы без избыточного переключателя. `tests/visual/rdg-active-example.cjs` и `tests/visual/rdg-offline-published-owners.cjs` проверяют настоящие Graph/Plan/Gendocen snapshots.

**Установленный у пользователя Viewer не обновляется автоматически.** Изменения исходников и опубликованных данных требуют отдельного обновления в браузере. Текущий source version и границы проверок — в [единой карте](RDG-CURRENT-STATE.md).
