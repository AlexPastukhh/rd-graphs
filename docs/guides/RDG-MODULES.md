# RDG — кодовые модули

> **СТАТУС: ДЕЙСТВУЮЩАЯ ДОКУМЕНТАЦИЯ ПОДСИСТЕМЫ В РАЗРАБОТКЕ.** Модули экспериментальны, контракт ещё нестабилен. Семантика и права: [RDG-ACTIVE-CONTRACT](RDG-ACTIVE-CONTRACT.md). Протокол 1 не является завершённой или принятой модульной системой и не означает приёмки Stage 4.

Протокол ниже относится к прежнему R/A owner. Он не расширяет `rdg-decision-v1`; фиксированные Decision kinds задаёт [схема профиля](../../tools/contracts/rdg-decision-v1.schema.json). [Границы текущей реализации](RDG-DEVELOPMENT-PLAN.md#оставшаяся-работа).

**Граница текущей работы:** развивать и менять контракты, реестр и код модулей только в задачах, непосредственно относящихся к модульной подсистеме. При другой разработке и общем рефакторинге сохранять её текущее поведение, не расширять и не перестраивать попутно. Тестовый пакет не подключать к рабочим owners. Существующие ограничения базовых типов и права writers продолжают действовать.

Базовый rdg-base v1 обязателен. Его код — существующие Graph writer, модель R/A, Plan owner и история. Закрытые списки типов/операций объявлены в tools/rdg-module-registry.json и используются writers. Канон остаётся частью Action. Типы Plan steps event/milestone/decision_gate не являются видами нод Graph или архивной моделью Decision/Option.

Расширение — **установленный пакет кода** и декларация в доверенном реестре. Entry протокола 1 — Python-файл rdg-module-<name>.py внутри tools, API_VERSION = 1. Owner выбирает только зарегистрированный ID/версию; путь к коду из запроса не принимается. Модуль может иметь Graph-часть, Plan-часть или обе и собственную проекцию истории. Реестр содержит requiresBase, разрешённые пары id/identitySpace отдельно для Graph/Plan, схемы сущностей и операции. Создание экземпляра блока AI или пользователем не регистрирует новый тип или код.

## Точки вызова кода

Общий resolver — tools/rdg-modules.py. Код получает копии входов; авторизация, CAS и запись остаются у host writers.

| Hook | Эффект протокола 1 |
| --- | --- |
| validate_entity(node, graph) | Проверка собственной типизированной сущности |
| graph_operation(operation, graph) | Эффект с node для объявленной create_entity/update_entity операции |
| validate_plan(data, plan) | Проверка собственных данных Plan |
| plan_operation(operation, plan) | Новое значение в своём moduleData[moduleId] |
| describe_history(event, owner) | Текст своей истории, без подмены типа события или удостоверения исполнения |

Входы и выходы проверяются закрытой схемой: text, integer, requirementRefs. Код может дополнительно проверять/вычислять значения. Модуль не подменяет базовые kinds, identity, права, принятые события и completion.

Новые группы эффектов, зависимости между пакетами, миграции, собственные типы Plan steps и frontend-renderers требуют расширения host-протокола и тестов. Версии кода/контрактов сохраняются для истории; смысл использованной версии нельзя менять.

Типизированные requirementRefs проверяются по canonical owners и правам чтения до Graph commit; Gendocen использует их, а не текст. Отключение не стирает существующие зависимости.

## Подключение и отключение

В owner хранятся modules — объект ID: версия (например rdg-test: 1) и disabledModules — список выключенных ID. Без modules действует база. Graph не включает пакет другому Graph или отдельному Plan. Проверяются код, версия и allowlist; подключение не выдаёт права.

В авторизованном Viewer: **«План во времени» → «Модули»**, кнопки «Подключить»/«Отключить» отдельно для Graph и Plan. Offline-снимок не разрешает запись. Тестовый пакет недоступен рабочему учебному owner.

Helper команды: configure_graph_modules, configure_plan_modules, module_operation, set_module_data. Они используют штатные transactionId, note и expected revisions. Нужны graph.configure_modules, graph.module_operation либо graph.write и отдельное plan.edit. Чтение требует своих прав.

Отключение запрещает новые операции, сохраняя данные и историю; чтение версионного контракта остаётся доступным. Это выключение активного поведения, а не удаление установленного файла. Повторное включение возвращает операции. Binding можно удалить до использования; при зависимых данных/истории удаление и смена версии требуют миграции. Автоматических миграций нет. Прежний context/nodeTypeExtensions сохранён как ограниченная совместимость.

Graph сохраняет modules_configured/module_event с проверенным происхождением и снимком эффекта. Текст Graph-события формируется модулем при записи, не из сегодняшней ноды. История Plan проецируется из его сохранённых версий. Сбой после durable acceptance требует штатного read-back/recovery и точного повтора.

## Тестовый пакет

tools/rdg-module-test.py — rdg-test v1, технический пакет без предметного смысла. Реестр разрешает пакет только тестовой паре owner module-test / rdg-module-test; сами тесты создают её во временных каталогах. Graph hook нормализует маркер, Plan hook вычисляет число слов, history hook формирует текст эффекта.

tests/rdg-modules.test.py проверяет реальные Helper/writers, права, CAS, повтор, переключение, Plan, историю и зависимости. tests/visual/rdg-modules.cjs вызывается из Python-теста с временным Helper; без его URL не запускается. Chromium-проверка не заменяет пользовательскую оценку UI и не доказывает установку Viewer.
