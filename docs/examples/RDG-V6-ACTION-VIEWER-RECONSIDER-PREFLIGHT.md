# Candidate RDG v6 — Viewer Action 2.0.3 и анализ последствий отмены

**Статус:** CANDIDATE / LIMITED / не изменение принятой модели графов. Этап продолжает [opt-in writer/reader](RDG-V6-ACTION-WRITER-READER-OPTIN.md), а не заменяет старые `Option/Decision` во всех графах.

**Более поздний отдельный этап:** [опциональный writer-пересмотр с собственной Action и обоснованной судьбой child R](RDG-V6-ACTION-RECONSIDERATION-WRITER.md). Ограничения ниже относятся к первоначальному read-only этапу.

## Реально работает

- `tools/rd-graph-viewer.user.js` v2.0.3 встроил актуальную `rdg-root-projection.js`. Для графов с `actionModel: "candidate-v6"` полный **R-only** обзор показывает выбранные дочерние Requirements через Action, но не выдает сам Action за R. В режиме подробностей видны отдельные выбранные и кандидатные Actions, их каноны, QRPE и исторический снимок выбора T1; выбранность **не доказывает** исполнения или достижения R. Старые `Option/Decision` остаются в прежнем режиме.
- Локальный Viewer при открытии подходящего учебного `graph.json` показывает Action и представление его канона. Такой `graph.json` есть в `tests/fixtures/rdg-v6-action-optin/graph.json`. Он пока **не зарегистрирован** как пользовательский граф каталога. Проверка полного графа проводилась с временным read-only индексом и настоящим содержимым этого файла.
- Состояние выбранного Action принимается для проекции только при наличии целостной связки: `selected`, T1 candidate/driver snapshots, одного подходящего `action_selected` события с actor/note, корректного драйвера R, и при отсутствии `templateOnly`/`exampleOnly`. Подмена T1 больше не делает причинную связь принятой.
- `tools/rdg-v6-action-reconsider-preflight.py` читает opt-in `graph.json` и без единой записи перечисляет child R выбранного Action, другие **подтверждённые действующие** вводящие Actions, downstream ссылки и открытые QRPE. Он **никогда** не разрешает фактическую отмену сам по себе и не проверяет реальные полномочия или внешние эффекты. Это отчёт для принятия решения в чате, не обязательный сохраняемый LensRun и не новый `External Dependencies` блок.

## Пример анализа последствий

```bash
cd /workspace/repos/rd-graphs
python3 tools/rdg-v6-action-reconsider-preflight.py \
  --graph tests/fixtures/rdg-v6-action-optin/graph.json --action-id A1
```

Для `A1` проверка обнаруживает введённые `R1` и `R2` без других установленных вводящих Actions и открытый `Q1`. Поэтому текущие требования **не следует удалять или деактивировать автоматически**. Даже когда альтернативный выбранный Action также вводит одну из R, это ещё не объясняет судьбу оставшихся R, законность изменения пользователя и реальные внешние эффекты. Подготовлен отдельный тест с двумя вводящими Actions для проверки такого случая.

## Чего пока нет

- **Нет** общего Lens-runner или AI evaluator канонов; хранящиеся canon cases отображаются, но не объявляются истинными автоматически.
- **Нет** операций `revoke_action`/`replace_selected_action`, санкционированного изменения R или компенсации совершённых эффектов в рабочем writer. Такие операции должны быть обычными Actions с собственными канонами/QRPE, обоснованным scope, проверкой других причин дочерних R, полномочиями и историей — они являются **отдельным следующим этапом**, а не побочным эффектом просмотра.
- **Нет** миграции legacy O/D, включения `candidate-v6` по умолчанию, обновления установленного Tampermonkey/Helper или подтверждённого браузерного UI E2E с реальными локальными разрешениями. Изменение `@version` в исходном userscript до 2.0.3 **не доказывает** его установку в браузере.

## Проверка

```bash
node --test tests/rdg-v6-action-viewer.test.cjs tests/rdg-v6-action-reconsider-preflight.test.cjs
node --test tests/*.test.cjs
```

Содержательные negative cases: старый Decision не потерян; невыбранный Action не становится причиной принятой R; поддельный T1 не даёт принятой ветви; без разрешения/доказательств отмены отчёт не выполняет никаких записей; иное вводящее Action сохраняет независимо оправданную R. **Запись рабочего графа производится только при выполнении установленных пользователем критериев документирования решений/планирования и отдельного надлежащего commit/authority**, не при каждом просмотре линзы.
