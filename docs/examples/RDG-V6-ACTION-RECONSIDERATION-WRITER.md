# Candidate v6 — изменение выбранного Action обычным Action пересмотра

**Статус:** LIMITed candidate implementation / opt-in `actionModel: "candidate-v6"`; **не** утверждённая схема по умолчанию и **не** внедрение в реальные рабочие графы. Продолжает [Action writer/reader](RDG-V6-ACTION-WRITER-READER-OPTIN.md) и [Viewer + предварительную проверку](RDG-V6-ACTION-VIEWER-RECONSIDER-PREFLIGHT.md). Дата среза: 2026-10-17.

**Последующая ограниченная стадия:** [подпись транзакции, проверка локального evidence и применение подготовленных Lens](RDG-V6-LENS-TRUSTED-PACKAGE-PILOT.md). Описанный ниже `approvalRef` сам по себе больше не является достаточным для записи: нужен подтверждённый trusted package.

## Реализованный переход

В opt-in writer появился `reconsider_action`. Это **материальная запись**, которая имеет смысл, когда действительно нужно сохранить пересматриваемое решение и причины его изменения. Она использует **отдельный обычный выбранный Action** (`reviewActionId`) для пересмотра ранее выбранного Action (`actionId`); оба являются Action с собственными ID. У Action пересмотра обязательны собственные canon cases и QRPE; без обоснованной оценки всех канонов и оформленного разрешения QRPE запись не допускается. В результате прежний Action получает `status: superseded`, его активные `INTRODUCES` архивируются, а событие `action_reconsidered` хранит прежний Action, прежние вводившие R связи, Action пересмотра, оценки канонов, snapshot решения и явное основание.

Дочерние R **не удаляются физически**. Для *каждой* ранее введённой R нужно указать индивидуальный вариант:

- `retain_supported`: оставить R активной, если другой выбранный Action действительно независимо вводит эту же R; все supporting Action IDs сверяются с текущим графом.
- `deactivate`: сделать R неактивной, **только** если нет другого выбранного вводящего Action, нет активных местных зависимостей/дочерних Actions, нет отдельного файла графа, чьё продолжение опирается на эту R, и есть явное обоснование. Root R и R другого owner не деактивируются.

`link_action_requirement` — отдельная event-bearing операция, позволяющая выбранному Action ввести **уже существующую** действующую R. Это обеспечивает случай общей R без создания ложной копии или требования выбирать лишь один способ. Типизированное событие `action_requirement_linked` сохраняет, кто и почему добавил независимую причинную связь.

Исторические Action не превращаются в новые Decision и не исчезают. Старые события выбора и T1 остаются; более поздняя исследовательская запись QRPE разрешена и **не переписывает** прежний snapshot. Можно пересмотреть Action, который сам раньше пересматривал другой Action: новый переход добавляет свою историю и не меняет предыдущую.

## Граница безопасности и полномочий

Изменение запрещается на legacy-графе без opt-in; старые операции `deactivate_requirement`/`reparent_requirement`, `select_option`/`add_option` и generic `update_node` не обходят этот переход в opt-in графе. Запись проходит обычную проверку `revision`/transactionId, package validation, catalog и read-back; ошибка не оставляет частично применённого решения. Внешняя дочерняя R/проекция обнаруживается по каталогу и блокирует деактивацию до отдельной согласованной multi-file процедуры.

Событие требует `by: "user"`, пояснение `note`, ссылку `approvalRef`, `contextVersion`, все `canonChecks` с evidence refs и разрешённые QRPE reviewer Action. **Но `by`, `approvalRef`, `contextVersion` и `evidenceRefs` сейчас являются данными события, а не независимо проверенными удостоверением пользователя, permission scope, свежестью evidence или истинностью канонов.** Допускается только изолированный учебный запуск/проверка; реальная авторизация, верификация evidence, подтверждённые side effects и compensation — отдельные обязательные gates до production. Нельзя утверждать, что сам writer доказал позволение изменять цели пользователя.

Отсутствие зависимости в пределах одного графа **не** доказывает отсутствия внешнего эффекта в реальной жизни; событие обоснования этого автоматически не исправляет. При неизвестном external effect, неподтверждённых сторонних input, существенной авторизации или взаимосвязанных файлах нельзя считать реальную отмену безопасной. Не требуется ни новый блок External Dependencies, ни обязательная запись каждого Lens-run: это отдельная операция для действительно документируемых решений и декомпозиции.

## Исполняемый образец

`tests/fixtures/rdg-v6-action-reconsidered/graph.json` — создан реальными функциями writer на синтетическом графе, не включён в рабочий каталог. В нём `A1` исторически выбрано и затем пересмотрено обычным `A-REVIEW`, что подтвердило причину отказа от прежнего выбора; `R2` деактивирована, но не удалена; `R1` осталась активной благодаря отдельному `A3`. Viewer 2.0.3 в режиме R-only показывает текущую `R1`; в подробном режиме история `A1` доступна в разделе альтернатив/истории, вместе с событием пересмотра.

```
R0 --DRIVES--> A1 [superseded] --INTRODUCES (archived)--> R1 [active], R2 [inactive]
R0 --DRIVES--> A3 [selected]  --INTRODUCES (active)--> R1 [active]
R0 --DRIVES--> A-REVIEW [selected] --action_reconsidered--> A1
```

## Проверка и ограничения этапа

```bash
cd /workspace/repos/rd-graphs
node --test tests/rdg-v6-action-reconsider-writer.test.cjs
node --test tests/rdg-v6-action-viewer.test.cjs
node --test tests/*.test.cjs
```

Тесты проверяют: материализацию пересмотра; индивидуальную судьбу child R; сохранение shared R; отказ от деактивации shared R; запрет прошлой операции без ревью; отмену при downstream/другом файле; отсутствие частичных записей при ложном actor, QRPE, каноне, неполных dispositions; immutable T1 и возможность новых QRPE; вторую волну пересмотра; отображение истории в Viewer.

**Ещё не реализовано:** выполнение работы, которую представляет Action; реальный Lens-runner с правами изменения графа; автоматическое содержательное вычисление canon cases/QRPE; проверка пользователя, approval provenance и source existence; безопасная компенсация уже совершённых внешних эффектов; migration legacy O/D; установленный Helper и браузерная копия Viewer. Новая возможность не делает сам Candidate v6 или предлагаемые PR автоматически committed.
