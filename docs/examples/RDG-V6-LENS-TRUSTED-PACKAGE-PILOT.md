# RDG Candidate v6 — trusted-package gate и применение подготовленных Lens к `graph.json`

**Состояние:** экспериментальный opt-in (`actionModel: "candidate-v6"`), НЕ новая нормативная семантика RDG и НЕ подключённый повсеместно Helper. Этот этап продолжает [пересмотр Action через Action](RDG-V6-ACTION-RECONSIDERATION-WRITER.md). Дата среза: 2026-10-17.

**Позднее исправление (2026-10-17):** [Integrity Remediation](RDG-V6-INTEGRITY-REMEDIATION-20261017.md) охватывает не только `reconsider_action`, но и `select_action`, `link_action_requirement`, `transition_qrpe`, input validation перед Lens и bound `Q-MAINT-EFFECTS`. Ниже описан исходный bounded pilot; его отдельные ограничения и маршруты могли быть расширены указанным исправлением.

## Что добавлено

`tools/rdg-v6-action-trust.py` проверяет *перед* изменяющей транзакцией `reconsider_action` подписанный HMAC-SHA256 пакет с `trustedApproval`, где подпись охватывает **полный список изменений**, ID транзакции, цель разрешения, заявленного исполнителя и срок (не более 15 минут). Ключ `RDG_V6_TRUST_KEY` должен поступать из внешнего доверенного окружения; в репозитории его нет и ключа по умолчанию нет. Отсутствующий, неправильный, просроченный допуск, несоответствие исполнителя или изменённые операции блокируют запись. Готового внешнего *issuer* подписи здесь **нет**: тесты создают временные ключи и подписывают только синтетические пакеты.

Для канонов и разрешённых QRPE существующие `evidenceRefs` проходят отдельную проверку ссылок вида `graph-node:<nodeId>@<sha256>`, где хеш вычислен от прежнего состояния реального узла `graph.json`. Ссылки на несуществующее, устаревшее или неподдерживаемое свидетельство отвергаются. Это **проверка локального источника и целостности**, а не доказательство истинности оценки канона, точности затрат, обратимости эффектов или связи с реальным человеком. Ссылки на внешние сайты, чаты, документы и внешние эффекты сейчас не принимаются как автоматически проверенные.

Проверенный транзакционный receipt (issuer principal, purpose, signature, expiry, transaction ID и хеш подписанных changes) записывается в `action_reconsidered` вместе с прежним T1, canonChecks и судьбой R. Сам секрет не сохраняется. Прямой вызов библиотеки `graph-apply.apply` без подтверждённого допуска не может выполнить `reconsider_action`; рабочим рубежом доверия остаётся CLI `graph-package.py`. Прямой доступ к файловой системе или секрету этой экспериментальной реализацией **не** защищается.

`tools/rdg-v6-lens-apply.cjs` применяет **одно неизменяемое подготовленное определение линзы** из `tests/fixtures/rdg-action-lens-pilot-v1.json` к разным рабочим opt-in-графам. Линза сохраняет собственную root-Requirement и структуру R/A/канонов/QRPE; в ответе указаны digests определения и target-графа, результат достижения root-R, выполненные проверочные Actions, открытые QRPE и предложения. Не создаётся clone Lens и **не записывается LensRun**. Вызов — специализированный ограниченный адаптер для двух конкретных линз, не универсальный graph-runtime или AI evaluator.

Для DRY проверяются фактически активные Requirements target-графа и значения `concept`. Пустой/неполный ввод не означает успеха; реальная спорная пара даёт открытый QRPE и незавершённую root-R. Для Maintenance сравнение берётся из существующего `Context`-узла target-графа (с provenance digest), а не выдумывается адаптером. Неизвестная стоимость, неполная полезность или `stale` приводят к `needs_evidence`. Выводы о стоимости **предварительные**, без внешнего fact-check.

Режим `--mode report` всегда заканчивается **нулём графовых записей**. Режим `--mode apply` доступен только ограниченной Maintenance Lens после предложения пересмотра и при наличии отдельного подписанного пакета с **ровно одной** подходящей операцией `reconsider_action`, адресованной тому же графу, выбранному A и ревизии. Дальше выполняется действующий транзакционный writer и его guards; само сообщение Lens не является разрешением менять граф.

## Настоящие учебные графы и проверки

- `tests/fixtures/rdg-v6-lens-dry-target/graph.json` — schemaVersion 1 с root-R и несколькими различимыми R/`concept`.
- `tests/fixtures/rdg-v6-lens-maintenance-target/graph.json` — schemaVersion 1 с выбранными A, собственным Context сравнительных свидетельств, канонами/QRPE пересматривающего A. Сгенерирован операциями candidate writer.
- `tests/rdg-v6-lens-real-application.test.cjs` — запуск DRY на разных target и Maintenance как чатовое решение, затем выполнение через подписанный пакет на изолированной копии.
- `tests/rdg-v6-action-reconsider-writer.test.cjs` — MAC, просроченное разрешение, изменённый пакет, неверный ключ, unsupported/unknown/stale локальные evidence, отсутствие частичных записей, защита shared R, предыдущей истории и межфайлового продолжения.

Примеры (без графовых записей):

```bash
cd /workspace/repos/rd-graphs
node tools/rdg-v6-lens-apply.cjs --graph tests/fixtures/rdg-v6-lens-dry-target/graph.json --lens dry --mode report
node tools/rdg-v6-lens-apply.cjs --graph tests/fixtures/rdg-v6-lens-maintenance-target/graph.json --lens maintenance --mode report
node --test tests/rdg-v6-lens-real-application.test.cjs tests/rdg-v6-action-reconsider-writer.test.cjs
```

Реальный `--mode apply` не имеет команды самовыдать себе разрешение. Для него нужен доверенный issuer подписанного `--package` и ключ в среде вызывающего writer, которые здесь **не установлены**. Подписание в тестах **не** означает user authorization. Ни один обычный проектный `graphs/workspaces/*/graph.json` или установленный Viewer/Helper этими тестами не меняется.

## Что по-прежнему не закончено

1. **Проверка пользовательской идентичности, полномочий на конкретный workspace и external evidence:** нужен отдельный authenticated issuer и доверенный канал выдачи capability/разрешения. Наличие HMAC доказывает доверенный ключ, а не что пользователь действительно сказал «да».
2. **Универсальное исполнение Lens, контекстных канонов и QRPE:** конкретные проверки DRY/Maintenance ещё используют специальные сравнения полей, не любой RDG Action/branch/experimental graph. Не каждый Action/R требуется сохранять; два критерия материализации R/A уже известны и не менялись.
3. **Фактические внешние эффекты и компенсация:** отмена выбранного Action не откатывает исполнение. Неизвестные downstream effects требуют отдельного исследования и решения.
4. **Принятие schema/migration O/D, профессиональный UI и Helper integration:** opt-in ограничение сохранено, старые графы и модель приложения по умолчанию не мигрированы. Внешних блоков Dependencies и обязательных LensRun не добавлялось.

**Следующий gate:** интеграция с реальной аутентифицированной выдачей разрешений, проверка источников beyond-local-graph, а затем полноценный R/A Lens runner с качественными критериями достижения целей на разных Context без принудительных записей.
