## F-O-01 / PR-06 — обзор прямых DEPENDS_ON в фокусах

**Что может улучшить:** при работе с конкретной R/A иногда нужна короткая текстовая навигация по прямым `DEPENDS_ON`, поскольку собственный фокус показывает лишь связи выбранной проекции. **Кандидат:** компактный read-only список прямых зависимостей с переходами по ID. **Почему не сейчас:** отдельная вкладка зависимостей может уже закрывать нужный путь; без обратной связи нет основания увеличивать сложность UI. **Revisit trigger:** подтверждённый сценарий, когда текущий просмотр мешает восстановить причину stale. **Статус PR-06:** pending/deferred; не реализовывать автоматически.

## F-O-02 / PR-07 — дополнительная полнота ручного core UI

**Что может улучшить:** ручной ввод `unresolvedAcknowledged` при допустимом unknown canon и отдельное `resolve_finding` с evidence. **Почему не сейчас:** Agent/CLI уже обеспечивают операции; полная форма каждого API-флага не обязана входить в базовый пользовательский маршрут. **Revisit trigger:** пользовательский запрос на законченный ручной workflow и проверка действительного отсутствие поля в текущей версии. **Статус PR-07:** pending/deferred; не реализовывать автоматически.

## F-O-03 / PR-08 — более точная семантическая регрессия и DRY

**Что может улучшить:** негативный контрактный тест на конкретный новый риск смыслового расхождения между core, writer, Viewer и документацией. **Текущий достаточный путь:** при каждой material правке добавлять адресное доказательство, использовать действующий контракт и точную generated UI parity. **Не делать:** универсальный второй validator, новую taxonomy или новые нормативные копии только ради количества. **Revisit trigger:** подтверждённое новое расхождение, не покрытое адресными тестами. **Статус PR-08:** pending/conditional, без отдельной обязательной работы.
