## Как закрывать пункты

1. Назвать конкретную пользовательскую ситуацию и источник требований; проверить существующую функцию и тест, не создавать второй writer или validator.
2. На временном owner проверить смысл, отрицательные случаи, CAS/retry/recovery, Graph/Structure и при необходимости Viewer. Зафиксировать exact вход/выход и затраты.
3. Обновить **владельца правила** (контракт/техническое ТЗ/содержание линз), этот backlog — только статусом/ссылкой, и [локальный UC](docs/use-cases/README.md), если меняется пользовательский маршрут.
4. Для runtime изменения пройти полный Docker CI и сверить source SHA/ZIP/READY; **Windows deploy и пользовательская UX-приёмка отдельно**, не следуют из `ready.json`. Для docs-only — docs audit и адресные документационные тесты.
5. Не выполнять live изменение owners/Registry, удаление данных, расширение grants, GitHub публикацию или установку Windows по одному пункту backlog; разрешение определяется отдельной задачей и [правилами Fortis](docs/use-cases/development.md#uc-rdg-005).
